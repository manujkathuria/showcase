# Task 002: Tick and depth tables and indexes

Status: Ready for Antigravity implementation. Tables and performance results described here are required deliverables, not completed work.

## Objective

Create `market.live_ticks` and `market.order_depth` for full-mode stock/futures snapshots, with indexes tied to latest-tick and replay queries. Synthetic dataset generation is a separate Go task: [Task 003](003-synthetic-market-seed.md). WebSocket simulation remains a later task.

Read `AGENTS.md`, `docs/project-brief.md`, and `docs/local-database.md`. This task is SQL-only; the Go data-ownership skill becomes applicable when implementing the Go generator/codecs, not for SQL table layout.

## Storage contract

Create schema `market`, owned by `streaming_owner`. Application data must not use `public`. Use ordinary PostgreSQL tables initially: this keeps the tick/depth foreign key straightforward. TimescaleDB is installed, but hypertables, chunking, compression, and retention policies are deferred until their workload and joint tick/depth retention contract are designed. Do not claim time-series scaling has been validated by this slice.

One tick represents one decoded stock/futures quote packet, not one complete WebSocket message. Order depth represents snapshot levels, not individual order events. Index packets have a different layout and are outside the initial full-mode dataset.

Required columns for `market.live_ticks`:

| Column | Type and contract |
| --- | --- |
| `id` | bigint generated identity primary key; storage identity only |
| `instrument_id` | bigint NOT NULL FK to `feed.instruments(id)`; no cascade delete |
| `stream_id` | uuid NOT NULL, generated by publisher; distinguishes recording sessions/streams |
| `sequence` | bigint NOT NULL, positive, packet sequence within stream; preserved on retries |
| `received_at` | timestamptz NOT NULL, application receive time |
| `exchange_at` | timestamptz nullable; absent/zero source timestamps become NULL |
| `last_trade_at` | timestamptz nullable |
| `last_price`, `average_price`, `open_price`, `high_price`, `low_price`, `close_price` | bigint NOT NULL; raw scaled price integers, nonnegative |
| `last_quantity`, `volume`, `total_buy_quantity`, `total_sell_quantity` | bigint NOT NULL, nonnegative |
| `open_interest`, `open_interest_high`, `open_interest_low` | bigint NOT NULL, nonnegative |

Use `UNIQUE (stream_id, sequence)` to reject duplicate recording identities. This constraint alone does not establish end-to-end exactly-once delivery. Do not derive identity from timestamps or prices: repeated market values and timestamp collisions are valid. Stream sequence order is recording order, not necessarily exchange-time order.

Retain raw price scaling; use instrument metadata to interpret it. Do not store prices as floating point. Inspect the source specification for numeric interpretation before claiming complete fidelity. Do not fabricate missing source timestamps as actual exchange timestamps.

Required columns for `market.order_depth`:

| Column | Type and contract |
| --- | --- |
| `tick_id` | bigint NOT NULL FK to `market.live_ticks(id)` |
| `side` | text NOT NULL, CHECK IN ('bid', 'ask') |
| `level` | smallint NOT NULL, CHECK BETWEEN 1 AND 5 |
| `price`, `quantity`, `order_count` | bigint NOT NULL, nonnegative raw integer values |

Use `PRIMARY KEY (tick_id, side, level)`. This prevents duplicate levels and also indexes snapshot retrieval. Do not add a redundant standalone `tick_id` index. Preserve zero-valued levels; do not interpret an empty level as a missing row.

Tick and its ten depth levels must be inserted in a single transaction. Row constraints do not enforce exactly ten children: add verification of fixture completeness and document this as a writer responsibility. No writer service is implemented in this task. No cascade deletes or seven-day retention policy until coordinated deletion is agreed.

## Initial indexes and queries

Add B-tree `(instrument_id, received_at DESC, id DESC)` for instrument-local latest and bounded-history queries.

Add B-tree `(received_at, id)` for deterministic replay across instruments. Document its ingest/storage cost rather than creating indexes on every column. The identity unique index serves source-stream identity checks; depth's primary key serves the join.

Verify these query shapes:

1. Latest tick: instrument filter, ORDER BY received_at DESC, id DESC, LIMIT 1.
2. Instrument history: instrument and half-open receive-time range, ORDER BY received_at, id, bounded LIMIT.
3. Replay: half-open receive-time range with keyset pagination using `(received_at, id) > (:cursor_time, :cursor_id)`, ORDER BY received_at, id, bounded LIMIT. Do not use OFFSET pagination.
4. Depth snapshot: filter by tick_id, ORDER BY side, level.
5. Replay with depth: limit ticks first in a subquery/CTE, then join depth; a page of 100 ticks should have 100 complete snapshots, not 100 depth rows. State that ordering of tied timestamps is deterministic storage order, not exchange ordering.
